# Corrections, reusable evidence, and resumption

## During the task

Treat new user messages as steering unless they clearly replace the goal. Update the affected brief and work; preserve accepted decisions and useful output. Ask only about a material conflict.

Convert concrete feedback into an observable change: identify what differs, which property matters, and how to check the revision. If the same approach fails repeatedly, diagnose access, environment, feasibility, data, or assumptions before rewriting another prompt.

Do not interpret a preference in one client project as a universal rule for other clients. Respect originals and client boundaries.

## Reuse what was actually successful

When existing authorized project continuity applies, save meaningful decisions, a verified result or working example, evidence pointers, blockers, and the next executable action. Read back the save as required by that workflow. Skip unchanged notes.

A useful reusable lesson links a trigger to a verified action and outcome. Preserve a working artifact or example where permitted. Separate "user preferred this", "agent inferred this", and "behavior was actually tested". Record a suspected lesson as provisional.

Use available verified lessons on later similar tasks. Do not claim training, automatic cross-chat access, or universal synchronization. If the original cannot be accessed, name that gap.

## Updating Prompt Fixer

Do not alter this plugin, global instructions, or personal memory just because a task generated feedback. The user can authorize a plugin update based on concrete examples. Then change the smallest relevant rule, preserve its identity, increment its version, validate the package, and forward-test representative behavior.

Assess practical effects using task completion, requirement fidelity, needless questions, corrective turns, time, and cost when observed. Small manual forward-tests check behavior; they do not prove a numeric productivity gain.

## Handoff

Leave the current goal, source/version pointers, accepted decisions, actual result and checks, unresolved dependencies, and one next action with required access. Respect the current project's established record instead of creating a parallel system.
